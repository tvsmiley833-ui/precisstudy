## Workflow (guides)
Edit `guides/<slug>.json` → `node scripts/apply-guide-json.mjs <slug>` → `node scripts/sync-home-counts.mjs` → `npm test` → commit → push → `npm run deploy`.
- Template/markup changes live in `scripts/generate-guide.mjs` and `scripts/guide-template/*`. Regenerate every page with `npm run guides:regen` (add `-- --check` to only report drift). Pages and generator are kept identical; `test/pages-match-generator.node.test.mjs` fails if a page is hand-edited or the template changes without regenerating. Never hand-patch a guide page, and use replacement *functions* (not strings) in `.replace()` when inserting guide text: `$'`/`$&` in text once spliced copies of the page into itself on `precalc`.
- Shared JS/CSS (`public/shared/guide-app.js`, `guide-polish.css`) need no regen. They are served as `?v=<hash>` with immutable caching: the hash is memoised per Worker process, so local `wrangler dev` can show stale JS/CSS. Verify with `fetch(url,{cache:'no-store'})` or check production. Cloudflare may also serve a stale HTML edge copy right after deploy; use `?cb=<ts>`.
- GateGuard hook: first Edit/Write/Bash on a new file needs a stated block (importers/callers, affected API, data schemas, verbatim user instruction). `rm -rf` anywhere in a chained command blocks the whole chain.
