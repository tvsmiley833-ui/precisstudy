## Daily workflow
| Task | Do this |
|---|---|
| Edit guide content | edit `guides/<slug>.json` → `npm run guides:regen` → `node scripts/sync-home-counts.mjs` → tests → commit → push → deploy |
| Change the guide template/markup | edit `scripts/generate-guide.mjs` or `scripts/guide-template/*` → `npm run guides:regen` (all 55 pages) |
| Change guide/page JavaScript | edit `client/guide-app.js` or `client/personality.js` → `npm run build:client` → commit both source and built file |
| Homepage / dashboard / other pages | edit `public/<page>/index.html` directly (they are not generated) |
| Verify | `npm run typecheck`, `npm test` (vitest + node tests) |

Rules the tests enforce (they fail with instructions if broken):
- Guide pages must equal `generateGuide(json)` exactly (`pages-match-generator`). Never hand-edit a guide page.
- `public/shared/guide-app.js` and `personality.js` are build output. Edit `client/`. (`client-build`). Keep `--tsconfig-raw={}` in the esbuild flags or it forces `"use strict"` from the repo tsconfig.
- Every inline `onclick=` etc. must call a function that exists (`inline-handlers`).
- Guide content integrity (`guide-content`): valid answers/units, no duplicate questions, no repeated flashcard term within a unit. Progress is keyed by card **term**.
- Insert guide text with `.replace(x, () => text)` (a function), never a string: `$'`/`$&` in text once spliced copies of the page into `precalc`.

Hooks to know: GateGuard asks for importers/callers/schema/verbatim instruction before the first edit or write of a new file, and for facts before the first Bash. State them and retry. Recovery switches are in the hook message.

Local preview: `preview_start studystacks-dev` (wrangler dev on :8787). It can serve stale shared JS/CSS (the `?v=<hash>` is memoised per process): refresh with `fetch(url,{cache:'reload'})` then reload, or restart. Production edge HTML can be stale for a minute after deploy: add `?cb=<random>`.

## Architecture notes worth knowing
- **Guides**: 55 guides, data in `guides/*.json` (units, concepts, flashcards, quiz, hardQuiz, workedExamples, examParts, diagrams, qrefHtml, memoryHtml). Concepts may carry `figs: [{svg, cap, label}]` (graphs shown under the concept). Diagrams/figs get `role="img"` + caption `aria-label` at generation.
- **Units are numbered by id = position.** Inserting a unit means shifting ids, plus a one-time progress migration (see `migratePhysicsUnits`, `migrateAlgebra2Units` in `src/progress-routes.ts`; local copy in `public/shared/mastery.js`). Also update `public/shared/unit-titles.js` then run `node scripts/gen-subject-units.mjs` (writes `src/subject-units-data.ts`).
- **Progress** (`/api/progress`, KV): per subject `{mastery, examples, cardsKnown, srs, unitOrder}`. `srs` = spaced-repetition schedule `{term: [box 1-5, dueMs, lastReviewedMs]}`, merged per card by newest review (`mergeSrs`).
- **localStorage keys**: `ssMastery_<key>`, `ss-last-subject` (+unit/concept for exact resume), `ss-unit-order-<slug>`, `ss-exam` (`{date,label}`), `ss-timer-mode`, `ss-dyslexia`, `ss-tts-voice`, `ss-tts-rate`, `ss-cal-time`, `ss-theme`.
- **Features shipped this week**: spaced-repetition due view + homepage banner (`?due=1` deep link) + account sync; `.ics` study-plan export; natural read-aloud + voice picker; dyslexia reading mode; Pomodoro on the study timer; drag-to-reorder units with auto-scroll and renumbering; exact-section resume; exam countdown (homepage banner, prefills study plan, dashboard Today's plan); homepage "Study Tools" section; Algebra II Unit 2 (completing the square, two sections).
